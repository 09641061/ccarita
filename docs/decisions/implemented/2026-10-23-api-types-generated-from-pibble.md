# Decision: API types generated from pibble's OpenAPI

Status: implemented

## Problem

The learning-center reference writes each resource interface by hand. Pibble has 68 operations and 56 schemas, and changes them step by step; hand-written copies drift silently, and the first sign is a blank field on screen.

## Decision

[api/openapi.json](../../../api/openapi.json) is pibble's contract, generated by Quarkus at build time and copied by `pnpm api:sync` (`scripts/sync-api.sh`). `openapi-typescript` turns it into `src/app/shared/infrastructure/api/pibble.schema.ts`, which exports one type per schema (`Appointment`, `BookAppointmentRequest`) and `paths`. Only infrastructure imports that file (`pnpm arch` rule `generated-schema-stays-in-infrastructure`): each context's `*.api.ts` types its requests and responses with it, and assemblers turn them into domain classes. CI regenerates the file and fails if it differs from the committed one.

## Alternatives considered

**Hand-written resource interfaces**, as in the reference. No tooling, but nothing notices when pibble renames or adds a field.

**A generated client** (`openapi-fetch`, OpenAPI Generator). Removes the endpoint classes, but bypasses or duplicates Angular's `HttpClient` interceptors and test utilities, and generated services are hard to read in review.

## Consequences

A change in pibble reaches the app as a diff in `api/openapi.json` and type errors where it matters. pibble's document marks no property as required, so every generated field is optional: assemblers check the fields they need and fail loudly when one is missing. Marking required fields in pibble (`@Schema(requiredMode = REQUIRED)`) would tighten the types without changing the app.
